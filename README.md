## Что работает

- Окно Windows на egui/eframe, интерфейс на русском.
- Панель «Подсветка клавиатуры» с управлением встроенными режимами. Вкладка «Своя сцена» и применение кадра из GUI удалены по запросу пользователя; сохранённые сцены продолжают загружаться. Эскиз кольца дока оставлен отдельно.
- В 0.12.2 исправлена ошибка «RGB IDs do not match the matrix» при смене встроенного режима: нулевая пользовательская RGB-таблица больше не блокирует операцию, которая её не изменяет. Возврат встроенного режима также не читает эту таблицу. Проверка индексов остаётся обязательной при записи собственного RGB-кадра.
- Перечисление реальных HID-интерфейсов AK820MAX и APEX.
- Студия из семи процедурных эффектов: цвет, градиент, волна, дыхание, круги, звёзды, локальный отклик на нажатие в редакторе.
- Слои, маски из отдельных клавиш, группы WASD/стрелки/F-ряд, две краски, направление, масштаб, скорость, фаза, смешивание, яркость и шкала времени.
- JSON-проекты и экспорт анимации в GIF. Пример: `examples/aurora.ajazz.json`.
- Сохранение статического RGB-кадра через CLI (из GUI удалено в0.12.1). Перед каждой записью — копия в `%LOCALAPPDATA%/AjazzStudio/backups`, затем проверка цветов чтением. Кнопка возврата предыдущей подсветки и восстановление из JSON-копии. Другие области настроек не записываются.
- Чтение информации AK820MAX, батареи, профиля и блоков настроек напрямую через HID, без службы производителя.
- Компоновщик экрана 128×128: часы, дата, заголовок, цвета, позиция, PNG/JPEG/GIF, экспорт PNG и JSON-макета. Медиа хранится отдельно.
- Офлайн-анализ файлов: SHA-256, размер, энтропия, строки, эвристические кандидаты таблицы векторов. Анализ не устанавливает совместимость прошивки.
- Редактор восьми ступеней DPI и цветов мыши (50–42000, 0 отключает ступень), частоты 125–8000 Гц, debounce 2–10 мс, LOD и Angle snapping. Чтение и запись работают напрямую через радиомаршрутизацию дока, без службы AJAZZ. Конкурирующая служба блокируется проверкой перед открытием устройства; штатную программу и её фоновый процесс нужно закрыть. Перед записью сохраняется исходный снимок, изменения проверяются чтением; предусмотрены возврат и импорт/экспорт параметров.
- Переназначение выбранных клавиш на обычные клавиши, мультимедиа, TGL и MT; создание пар RS/SOCD с четырьмя правилами приоритета. Обе клавиши пары меняются вместе. Копия, проверка чтением, возврат и восстановление из снимка. Запись этих типов проверена по USB с возвратом шести блоков; их физическое поведение при нажатии ещё требует проверки. Fn пока защищён от перезаписи, макросы назначаются отдельным редактором вместе с банком действий.
- DKS: четыре действия по двум точкам нажатия и двум точкам отпускания, пороги 0,1–3,3 мм, отключение/нажатие/удержание на каждом этапе. Таблица и назначение сохраняются и возвращаются вместе; общая ячейка другой клавиши не изменяется. Цикл записи/чтения/возврата по USB прошёл; физическая проверка ещё нужна.
- Единый выбор USB/2.4 GHz для чтения, поклавишного кадра, встроенных эффектов, магнитных и общих настроек. Запись привязана к интерфейсу исходного снимка. Пользовательский режим записывается как 128, читается как 20; перед RGB-таблицей сначала включается этот режим, как на сайте.
- Встроенные режимы клавиатуры: выбор, цвет/RGB, яркость, скорость и направление. Автоматическое применение через 300 мс после последней правки, как на сайте. Короткая операция 0x23 больше не перечитывает RGB-матрицу: измерено 0,28 с вместо 1,32 с через 2.4G. Пользователь подтвердил быстрый красный из GUI. На 1.30 GET возвращает белый/RGB даже после видимого красного: остальные параметры проверяются чтением, цвет — ACK и визуально. Для возврата следующей правки сохраняется последняя подтверждённая команда этой сессии; после нового чтения исходный цвет неизвестен.
- Сочетания с одним/двумя модификаторами и обычной клавишей (CB), семь действий мыши с клавиатуры, все17 consumer-функций списка сайта. Девять циклов записи/чтения/возврата CB и мыши на F12 прошли через 2.4G. Локальное поле «Тест ввода» позволяет проверить реальное выполнение в окне приложения; системного перехвата клавиш нет.
- Редактор аппаратных макросов: клавиатура и кнопки мыши, задержки, порядок действий, три режима повтора, назначение выбранной клавише, JSON-импорт/экспорт и совместный возврат банка/назначений. Проверены запись, чтение и возврат банка и F12 для трёх режимов через 2.4G. Физическое выполнение ещё требует проверки.
- Магнитные настройки выбранных клавиш: точка срабатывания, RT нажатия/отпускания, режим по всему ходу, непрерывный RT и тип свитча. Другие клавиши и неизвестные флаги сохраняются. Резервная копия и проверяемый возврат.
- Общие настройки клавиатуры: сон, мёртвые зоны, стабилизация, автокалибровка и уровень задержки; копия, запись, проверка и возврат. В 0.5 каждый из шести параметров отдельно изменён, проверен чтением и возвращён; пользователь подтвердил нормальный ввод после тестов. Добавлена пауза 200 мс после постоянной записи перед проверочным чтением. Точная причина прежнего сбоя радиосвязи ещё не установлена.
- Прямое чтение версии экрана дока через HID, без службы производителя: подтверждён OLEDV104. Чтение версии не определяет совместимость будущего обновления.
- Прямая загрузка текущего кадра 128×128 в один из пяти слотов дока и GIF-анимации из 2–218 кадров с общей задержкой 20–255 мс. Пользователь подтвердил изображение и анимацию. Декоративная линия отключается. Протокол не возвращает прежние пиксели: сохраняется запись новой загрузки, а не резервная копия старого изображения. Часы в этой вкладке рисуются как неподвижная картинка; автономные часы доступны среди функциональных страниц.
- Установка времени штатных часов дока с компьютера. Обратное чтение времени протоколом не предусмотрено; результат требует просмотра штатной страницы часов.
- Сон мыши по 2.4G: 0–3600 секунд; 0 отключает сон. Цикл 20→300→20 секунд подтверждён чтением с сохранением остальных полей.
- Отдельный редактор кнопок мыши: клики, вперёд/назад, смена DPI, колесо, клавиша или сочетание с Ctrl/Shift/Alt/Win, отключение кнопки. Одна физическая кнопка обязательно сохраняет левый клик. Служебные и неизвестные назначения защищены; есть копии, проверка и возврат.
- Автосохранение рабочей сцены и макета экрана в `%LOCALAPPDATA%/AjazzStudio/session.json`, атомарная замена JSON-проектов и блокировка закрытия во время аппаратной операции.

Предпросмотр кольца дока использует 16 условных точек. Реальное число светодиодов, их порядок и возможность прямой адресации ещё не установлены. Автономная загрузка своей анимации в клавиатуру не реализована: прошивка 1.30 сообщает лимит GIF 0 кадров, у точного профиля сайта нет isShowGifEffect. Экспериментальная передача цветовых таблиц с компьютера оставлена в отдельной диагностике; она медленная и не заменяет загрузку в память. В диагностике есть выбор USB/2.4G, интервал, один проход или повтор, остановка с возвратом исходной подсветки. Редактор при этом остаётся активным. USB и радиоканал подтверждены визуально пользователем; исходные настройки после обоих тестов совпали. Используется команда 0x24, как в прежнем Lighting Lab; обновление всех клавиш по пакетам может быть видно. Запись только в RAM и ресурс сохранений прошивки не установлены. Подробности — в [ANIMATION.md](docs/ANIMATION.md). Отклик на клавиши не является системным перехватом ввода.

Пробные временные RGB-пакеты 0x35 и 0x32 через 2.4 GHz пока не дали видимой анимации на этой ревизии. Получение ACK не считается успехом вывода. Рабочая статическая подсветка сохраняется после выключения/включения клавиатуры.

В 0.4 добавлены интервал 10 мс между пакетами клавиатуры и остановка при уведомлениях 0xFC о сне/потере связи. Пять полных чтений подряд прошли после переподключения. Это мера снижения нагрузки и корректная обработка событий, но не подтверждение устранения первопричины зависания приёмника. При мигающей R и отсутствии ввода помогло переподключение донгла в тот же порт; затем все шесть блоков совпали с исходными.

## Что ещё не готово

Именованные аппаратные профили, дополнительные магнитные функции (калибровка и тест хода), расширение Fn, часть настроек мыши, собственные RGB-эффекты дока и дальнейшие функции экранной прошивки. Автономная загрузка своих RGB-анимаций клавиатуры остаётся неподтверждённой. Полная матрица: [docs/FEATURES.md](docs/FEATURES.md).

После подключения клавиатуры на сайте получили правильные ответы через FF80: версия 1.30, внутренний VID/PID 0C45:80A0 (USB-приёмник — 0C45:FEFC). Снимок и цикл «запись сцены → чтение → восстановление» прошли на устройстве. Назначения, RT, DKS и game mode после теста совпали с исходными байтами. Пользователь подтвердил видимую смену цветов на клавиатуре и появление параметров мыши в нашем интерфейсе. Другие ревизии доступны только для чтения.

Штатный endpoint для `dev_id=1759` ранее возвращал `Record not found`. Позже AJAZZ прислал точный офлайн-пакет для ID1755/1759; его OLED-компонент стал базой модификации экранного кода. Установщик драйвера и `iot_driver.exe` сами по себе не являются прошивкой микроконтроллера.

## Запуск

Готовые переносимые файлы находятся в `dist/` после упаковки. Для запуска `ajazz-studio.exe` не нужны Python или Node. Клавиатура работает напрямую через HID; мышь и экран дока тоже используют прямой HID. Штатная программа AJAZZ и её фоновая служба должны быть закрыты.

Сборка обычным Windows MSVC toolchain: Rust stable и Visual Studio Build Tools с C++/Windows SDK.

```powershell
cargo run --locked --bin ajazz-studio
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo fmt --all -- --check
```

На исследовательском компьютере установлен Rust GNU. Локальный w64devkit в `.tools/w64devkit` используется скриптом, который задаёт окружение только для своего процесса:

```powershell
.\scripts\dev.ps1 run
.\scripts\dev.ps1 test
.\scripts\dev.ps1 clippy
.\scripts\dev.ps1 release
```

GNU-сборка использует C runtime из Rust и инструменты w64devkit. Смешивать его с UCRT-библиотеками LLVM MinGW нельзя. Точные версии собранных зависимостей закреплены в `Cargo.lock`.

`snapshot` отправляет только запросы чтения настроек из известного протокола. Это не дамп прошивки и не полная резервная копия: макросы, например, в этот снимок пока не включены. `lighting-apply` записывает только RGB и режим подсветки; возвращает путь автоматической копии для `lighting-restore`. Не запускайте эти операции одновременно со сменой настроек в штатном драйвере. В CLI нет raw-send, erase, bootloader или flash. `radio-status` читает снимок службы, который может содержать устаревшее значение батареи; флаг `service_online_flag` выводится отдельно.

## Структура

`src/model.rs` — формат проектов; `lighting.rs` — независимый движок эффектов; `screen.rs` — экран и медиа; `protocol.rs` — кодеки; `hardware.rs` — HID и чтение; `mouse_hid.rs` — прямой RF-транспорт мыши; `keyboard_playback.rs` — воспроизведение с восстановлением; `local_bridge.rs` — оставленная диагностика прежнего gRPC-web моста; `mouse.rs` и `keyboard_settings.rs` — проверяемые транзакции; `storage.rs` — копии и атомарное сохранение; `firmware.rs` — анализ файлов; `ui.rs` — интерфейс.

`research/vendor/` и `research/local/` исключены из Git. Здесь находятся оригинальные материалы для анализа и локальные диагностические снимки. Их происхождение и контрольные суммы записаны в `research/source-manifest.json`. Исполняемый код производителя не импортируется в приложение.
