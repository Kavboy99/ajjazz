# Встроенные алгоритмы подсветки: результат исследования

17 октября 2026. Цель — новые алгоритмы, выполняемые самой клавиатурой и выбираемые из списка приложения. Именованные варианты существующих эффектов не решают эту задачу. Эксперимент с пресетами отменён и не выпущен; установленное приложение остаётся 0.12.1.

## Обновление на подключённом сайте

Проверен сайт https://ajazz.driveall.cn/settings в Edge с AK820MAX, подключённой пользователем по USB. В разделе «Обновить» показаны v1.30 и «Уже последняя версия». Нажатие «Проверить обновления» показало «Нет доступных обновлений», но журнал этой же вкладки содержит `Unexpected end of JSON input` при проверке обновлений. Поэтому надпись не подтверждает, что 1.30 — последняя существующая прошивка.

Повторное получение `https://ajazz.driveall.cn/update.json`, включая запрос с Cache-Control:no-cache и Referer страницы настроек, вернуло HTTP200 с пустым телом. В текущем JS функция `o$` читает этот каталог, `c$` выбирает запись по внутреннему PID и точному HID-имени. Затем используются `latestVersion.file_name`, `isHex` и параметры ISP либо OTA. При пустом каталоге имя файла получить из этого пути нельзя. JS сайта совпал с ранее исследованным: SHA256 `7edaa333a9272feebc8406c33ea07f43cb8051c8b30f7eda8693e9071142638d`.

Доказательства: `research/local/keyboard-browser-update-errors-013.json`, `research/local/custom-modes-013-source-proof.json`, `artifacts/keyboard-update-connected-013.png`. Обновление прошивки не запускалось.

## Что действительно разобрано в бинарном коде

Из ранее полученного пакета восстановления доступен образ с SHA256 `ef67c8a05093961b799eebc39804b89707459c72477c6f26bf25e946b5810850`. Теперь идентичность проверена не только по INI обновлятора, но и по блоку самого образа по адресу0x9000:

| Поле | Разобранный образ | Подключённая клавиатура |
|---|---|---|
| VID:PID | 0C45:8033 | 0C45:80A0 |
| Firmware | 1.04 | 1.30 |
| Manufacturer | 0166 | 0166 |
| Product | 0000 | 1004 |

Совместимость не установлена. Название SN34F280 в пакете не является независимой идентификацией контроллера вашей платы. Адреса ниже относятся только к указанному хешу и не могут автоматически переноситься на80A0.

| Узел близкого образа | Адрес/результат |
|---|---|
| Обработчик vendor GET/SET | 0xD218 |
| Выбор области для SET0x23 | 0xD43A → 0x9600 |
| Обновление страницы flash | 0x380C; виден read/modify/write страницы512 байт |
| Перезагрузка параметров после SET0x23 | 0xD520 → 0x8EC |
| Параметры эффекта в RAM | 0x200002EA |
| Таблица инициализации | TBB0xCDCA, 25 записей |
| Таблица шага анимации | TBB0x651A, 31 запись |
| Три канала цветов | 0x20002BEC / 0x20002C6A / 0x20002CE8 |
| Буфер интенсивности | 0x20002D66 |

Номер команды эффекта, индекс инициализации и индекс шага — разные значения. Например, wire-mode11 выбирает инициализацию0xBF0C, которая задаёт runtime-index10; его шаг — функция0xBE84. В таблице инициализации индексы20–23 ведут к NOP, а24 — к загрузке пользовательского неподвижного кадра. Наличие пустых веток не делает их готовым API расширения.

## Восстановленный шаг волны

Функция0xBE84 обновляет21 фазу, используя таблицу из96 значений и направление, затем записывает интенсивность по6 индексам матрицы каждой группы. Индексы в таблице могут повторяться; это учтено. Поверхность и карта светодиодов этого образа не объявляются картой подключённой ULTRA.

Реконструкция:

```text
для каждой группы из21:
    phase[group] = (phase[group] + (direction ? 1 : -1)) mod96
    value = LUT[phase[group]]
    для шести индексов матрицы группы:
        intensity[index] = value
```

В Unicorn исполнялись исходные ARM-байты только этой функции, с изолированными ROM и RAM. Результаты192 последовательных шагов, по полному циклу в каждом направлении, сравнивались с реконструкцией: все байты фаз и интенсивностей совпали. Каждая запись эмулятора ограничена буферами фаз/интенсивности и стеком. USB, MMIO, полный запуск vendor-программы и запись на устройство отсутствовали. Это проверка понимания близкого образа, не проверка нового эффекта на80A0.

Воспроизведение:

```powershell
python tools/analyze_candidate_lighting.py
python tools/emulate_candidate_wave.py
```

Опциональные зависимости исследования перечислены в `tools/requirements-firmware.txt`; исполняемому приложению они не нужны. Скрипты привязаны к хешу образа и отклоняют другой файл. Выходы: `research/local/candidate-lighting-dispatch.json`, `.asm`, `candidate-wave-emulation-proof.json`. Патч или образ для прошивки не создавались.

## Проверка возможного чтения на настоящей клавиатуре

После перевода в USB выполнены только ограниченные GET0x10/11/13. Из близкого образа следовала гипотеза чтения соседней области, но настоящий80A0 вернул при GET13 с offset16 тот же блок, что с offset0. Это не произвольное чтение flash. Большой перебор смещений не выполнялся. Информация об устройстве, общие настройки и подсветка до/после совпали.

Доказательство: `research/local/keyboard-usb-read-window-probe.json`; воспроизводимый ограниченный инструмент — `tools/probe_keyboard_read_window.py`. Не отправлялись SET, Feature ISP, reset, boot, erase, program или команды0x81–0x86. При работе сайта этот инструмент одновременно не запускается.

## Что блокирует перенос на80A0

Нужен точный образ80A0/1.30 либо подтверждённый способ его чтения. Затем требуется установить контроллер и плату, адреса обработчиков/таймера/буферов именно этой версии, границы кода и областей настроек/Hall-калибровки/радиопараметров, а также рабочее восстановление. Доступный чужой образ, пакет с одним похожим названием или пустой каталог сайта не заменяют эти данные.

Ранее скачанный `AK820MAX-Ultra-Upgrade` и одноимённый RAR — HTML-страница проверки браузера11991 байт, не архив. Наличие интерфейса обновления на сайте само по себе не даёт файл установленной1.30 и не подтверждает возможность его обратного чтения.

Конкретный запрос для получения исходного файла у производителя/импортёра (не отправлялся): «Нужен пакет штатной прошивки или recovery для AK820MAX ULTRA, Soldier King Magnetic, EAN6976412985287, USB0C45:80A0, manufacturer0166, product1004, firmware1.30. Нужны BIN/HEX либо обновлятор со встроенным образом, идентификатор платы/MCU и способ восстановления без утраты Hall-калибровки и сопряжения с донглом. Онлайн-каталог update.json сейчас возвращает пустое тело».

Новые автономные режимы в приложение пока не добавлены: без переноса и аппаратной проверки они не объявляются работающими.


## Дополнительные режимы30–33 из скриншота, 18 октября 2026

Проверен актуальный `lighting-DzPku7KQ.js`:8141 байт, SHA256 `f3fff898e05a0c6e4dbf96d04d15b48d36bda3171965e7610491dcd874d3f4ac`, совпадает с сохранённой копией. Показанные объекты находятся в `appendLightingModeList`. Их поля — название, ключ перевода, номер, иконка и доступность элементов настройки; функций расчёта кадров в этих объектах нет.

Номера30–33 включены через `customEffect:[26,27,28,29,30,31,32,33]` в конфигурациях `tU` (AJAZZ SK98,0C45:800F) и `FG` (его2.4G Dongle,0C45:FEFA). Точные профили нашей клавиатуры `YU` (80A0) и `qG` (FEFC) не содержат этого списка. Загрузчик добавляет элементы `appendLightingModeList` только при явном присутствии номера в `lightingConfig.customEffect`.

При выборе режима `mZ/setLEDEffect` помещает номер в byte0 блока16 байт команды0x23; остальные байты — параметры. Объект описания или JavaScript-функция на клавиатуру не загружаются. Поэтому добавление такого объекта в список само по себе не устанавливает новый алгоритм. Отсутствие номера в профиле не доказывает отсутствие скрытого обработчика в firmware: номера30–33 на80A0 в этой проверке не отправлялись и не объявляются поддержанными.

Воспроизводимые выдержки, таблица профилей и границы вывода: `research/local/extra-lighting-30-33-audit.json`.

## Получение образа: новый результат 18 октября 2026

Получен полный официальный datasheet SN34F280 v1.7 (11 079 913 байт, 569 страниц). Разделы 22.8.5 и 23 подтверждают условный путь чтения через SWD при CS0; CS1/CS3 запрещают чтение MM через ICE, а снятие защиты стирает код. Описаны физические адреса MM/SM и восстановление отладочных выводов через BOOT, которое не снимает CS. Это документация семейства, не подтверждение MCU конкретной AK820MAX.

План получения, адреса с границами применимости, хеш документа, разбор актуального SonixFlasherC и готовый запрос recovery производителю: `docs/FIRMWARE-ACQUISITION.md`. Доказательства: `research/local/firmware-acquisition-evidence-20261018.json`. Каталог update.json повторно пуст. Образ 80A0/1.30 не получен; на устройство в этой части исследования команды не отправлялись. Для аппаратного продолжения нужна маркировка MCU/PCB.
