# Показатели компьютера — Studio 0.25.2

## Что изменилось

Основной счётчик FPS читает события DXGI/D3D9 непосредственно через Windows ETW
внутри сборщика Studio. Он работает непрерывно, без перезапуска внешнего процесса
каждые десять секунд. PresentMon 2.6.0 остаётся резервным источником для других
графических API. Потоки не складываются: предпочтение отдаётся свежим измерениям
нативного счётчика, при их отсутствии используется резервный источник.

Это исправление дополняет разбор заголовка PresentMon (`msBetweenPresents`).
Предыдущая проверка дала 230–239 FPS, но затем пользователь воспроизвёл отсутствие
FPS даже с активной Overwatch: во внешнем сборщике не было входных строк.
Поэтому одной правки CSV было недостаточно. При проверке нового пути в меню
Overwatch получены примерно 60 FPS и реальные температуры CPU/GPU. Это измерения
конкретной проверки, а не обещание постоянной частоты кадров.

Пользователь подтвердил FPS на физическом доке, затем заметил задержку примерно
в секунду. В 0.25.2 нативные события доставляются с принудительным сбросом только
собственной ETW-сессии каждые 100 мс; время события учитывается по QPC, а не по
времени доставки пачки. Окно FPS — последние 350 мс (минимум три наблюдения для
низкой частоты). Локальный сборщик обновляется каждые 200 мс. Видимые игровые
страницы получают данные раз в 250 мс; остальные — раз в секунду.
CPU/RAM и показатели видеокарты сохраняют секундный опрос. Статус страниц читается
раз в секунду, таймер — только на его странице; повторные полные проверки
возможностей перед каждым таким чтением убраны внутри уже проверенной сессии.
Проверки модели при открытии HID, последовательности и CRC подтверждений сохранены.
Числа выше задают интервалы обработки, а не гарантируют точную задержку панели.
На подключённом доке без параллельного частого чтения получены 27 новых измерений
за 8,426 с (около 3,2 в секунду; длительность USB-операций ограничивает темп).
Отдельная проверка подтвердила выбор `Windows ETW` для Overwatch, отсутствие
ошибок сессии и доставку последнего наблюдения примерно за 0,1 с.
Пользователь сравнил новую версию с игровым счётчиком и подтвердил:
«Да, теперь заметно быстрее». Полная задержка физических пикселей отдельно
прибором не измерялась.

Захват использует ETW Windows, без внедрения DLL в игру и без сочетаний клавиш.
DXGI/D3D9 обрабатываются встроенным счётчиком, остальные API — PresentMon; гарантировать работу с каждым
защищённым процессом/драйвером нельзя. FPS — частота presents приложения, не
сумма окон/цепочек. После Alt+Tab сохраняется последняя активная игра, устаревшие
наблюдения через 2 секунды становятся недоступными. При единственной игре выбор
возможен даже при запуске Studio поверх неё.

Первый захват FPS и доступ к CPU требуют разрешения Windows для отдельного
фонового сборщика. Сам редактор не перезапускается от администратора. Сборщик
передаёт только показания и настройки захвата по локальному соединению с
случайным ключом; завершается после закрытия Studio. Службы, системные группы,
настройки разгона и охлаждения приложение не меняет.

## Датчики

- CPU: LibreHardwareMonitor 0.9.6, Package/Tctl, °C. Для доступа нужен PawnIO.
- GPU: NVML установленного драйвера NVIDIA — загрузка, VRAM, температура, мощность.
- Накопители: Windows StorageDeviceTemperatureProperty, максимум доступных дисков.
- SYS: доступный System/Motherboard из LibreHardwareMonitor. Датчик может отсутствовать.

PawnIO 2.1.0 установлен с разрешения пользователя, подпись namazso действительна,
установщик завершился кодом 0, драйвер Running. Пакет взят из официальных ресурсов
LibreHardwareMonitor, SHA256 a3a46226c5e2824f4cdd42be0eecbabfc672c86f7889710f5ab1e6ad385b47a0.
На другом компьютере компонент включается в Studio: Дополнительно → Обновления →
FPS и датчики → Включить. Установщик включён в пакет; Windows запрашивает разрешение.
Studio не устанавливает драйвер без этого действия пользователя. Отсутствующий CPU, недоступная температура
и остановленная игра обозначаются прочерком. Нулевой неподтверждённый CPU не показывается.

Нативные и внешние датчики опрашиваются отдельно от интерфейса, с ограниченным
сроком свежести. Состав датчиков зависит от оборудования. Файлы сборщика проверяются
по встроенному манифесту SHA256 перед запуском.

## Новые экраны OLED UI2

- **В игре:** крупный FPS 30 px, средний интервал между presents, CPU/GPU °C 20 px.
- **Температуры:** CPU, GPU, DISK, SYS в четырёх ячейках с крупными значениями.
- **Видеокарта:** GPU %, мощность W, VRAM %, температура GPU.
- **Пульс системы:** CPU/GPU % и реальные последние 32 наблюдения. История собирается
  в RAM дока по номеру измерения; повтор одного пакета не добавляет точку.

Цвета задаются общим стилем экранов. Обновления автоматические, отдельного запуска
показателей не требуется. Studio должна работать, в том числе свёрнутой в трей.
Кнопка дока переключает сохранённые экраны и без приложения; свежие показатели
компьютера без работающей Studio поступать не могут.

Новые виды страниц требуют отдельной установки проверенного образа OLED UI2.
До этого они доступны как предпросмотр/черновик; отправка на старый OLED блокируется
до изменения сохранённого списка. Старые виды 0–8 и 16/32-байтные измерения совместимы.
Фото и GIF не стираются. Новая телеметрия занимает 48 байт с CRC, передаются числа,
а не картинки. Температуры и история не записываются во flash.

## Проверки и границы

142 теста библиотеки и 8 тестов интерфейса прошли; clippy и release-сборка прошли.
Проверены настоящий заголовок PresentMon,
устаревание FPS, CRC и диапазоны, протокол локального сборщика, задержанный handshake
и повтор сохранения при кратковременной блокировке файла Windows.
Дополнительно проверены разделение цепочек отрисовки, исключение тестовых и
неуспешных Present, выбор нативного источника и переход к свежему резервному.
Собственная ETW-сессия имеет уникальное имя и закрывается при завершении сборщика;
Studio не останавливает чужие сессии, службы или оверлеи.

ARM проверяет прежние экраны, переходы Stop/native, фото/GIF, сохранение списка,
12 новых пиксельно совпадающих сцен (живые/нет данных/крайние значения), 384 одиночных
повреждения каждого расширенного вектора и переключение новых страниц задней кнопкой.
Предпросмотр строится теми же шрифтами и координатами, что код MCU. Эта проверка
не заменяет физическую установку, оценку читаемости и аппаратное восстановление.
