# Быстрая подсветка AK820MAX ULTRA: результат проверки 18 октября 2026

## Состояние задачи

Плавность собственных эффектов на всей клавиатуре, сравнимая со штатными эффектами, **не достигнута**. Рабочий путь AJAZZ Studio 0.13.1 — сокращённые записи сохранённых цветов SET0x24. На USB для всей клавиатуры измерено около7.7 кадров/с; около29 кадров/с получено только для F-ряда. Целевые16/33 мс в интерфейсе не означают такую фактическую частоту.

Пользователь сообщил, что сейчас доступно только USB-подключение. Вскрытие и чтение маркировки платы не требуются для повторения уже выполненных опытов и не запрашиваются повторно.

## Проверка официального SDK

Разобраны опубликованные пакеты `@hfd-sdk/keyboard-sdk@2.0.2` и `@hfd-sdk/keyboard-kit@1.1.0`, без установки и запуска их кода. Первичные источники:

- https://docs.driveall.cn/keyboard/lighting.html
- https://docs.driveall.cn/kit/ai-lighting.html
- https://www.npmjs.com/package/@hfd-sdk/keyboard-sdk

USB-ветка `setMusicData` использует0x32 и компактные записи `[ID,R,G,B]` физических клавиш. Для нашей раскладки это82 записи/328 байт, шесть64-байтовых HID-пакетов с полезной нагрузкой56/56/56/56/56/48 байт. Это отличается от512-байтовой таблицы сохранённых цветов. Вызов из keyboard-kit не содержит отдельного включения нового режима.

| Проверка на0C45:80A0 /1.30 | Подтверждения USB | Наблюдение пользователя | Возврат шести блоков |
|---|---|---|---|
| Компактный0x32, повторный опыт80с | Принимались; передача кадра обычно21–25мс | «прежняя» | Совпали |
| Компактный0x32 после выбора custom128 и пары CUSTOM_FUNCTION_ON/OFF0x30/31,60с | Принимались | «нету» | Совпали |

Первый80-секундный опыт также завершился с возвратом, но пользователь не успел его посмотреть. Его нельзя считать ни положительным, ни отрицательным визуальным результатом. Повторный и дополнительный опыты дали отрицательные наблюдения. Быстрый ACK не доказывает обновление светодиодов; расчёт FPS по этим ACK не публикуется как скорость работающей подсветки.

Инструмент: `tools/probe_keyboard_sdk_compact.py`. Сырые результаты: `research/local/keyboard-sdk-compact-first-proof.json`, `keyboard-sdk-compact-proof.json`, `keyboard-sdk-custom-gate-proof.json`. Подтверждения пользователя и сводные показатели: `research/local/keyboard-fast-rgb-audit-20261018.json`.

В `src/protocol.rs` сохранён проверяемый кодек компактной таблицы и тест её размеров, порядка ID и заголовков. Проигрыватель и GUI на этот путь **не переключены**, потому что видимая работа не подтверждена. Новый бинарный релиз с обещанием ускорения не выпущен.

## Оставшиеся архивы и прошивка

Дополнительно распакован без запуска установщик `AJAZZ_AK820MAX 单模&三模RGB _键盘驱动_V1.0.exe`, SHA256 `b78d89836160f27c8340a112aecaa51cdbf70ec484a4941abcaf1ec97baa2704`. Его `Dev/kb/Wired/KB.ini` указывает258A:010C, а `Thr/KB.ini` — ещё3554:FA09 для радио. Это другая ревизия; совпадение коммерческого названия не устанавливает совместимость. Пакет не использовался для управления нашей клавиатурой.

В трёх локальных ZIP-снимках веб-драйвера `ajazz-ui-artifact-260522-1029`, `260604-0728`, `261016-0800` нет файлов с именами update/firmware либо расширениями BIN/HEX/UFW/WASM. Это результат проверки имён внутри архивов, а не доказательство отсутствия любого закодированного содержимого в JavaScript. Репозиторий трекера описывает архивирование клиентской части сайта: https://github.com/xyzmean/ajazz-driver-artifact .

Публичный проект OpenAula относится к AULA Mini60HE Pro с другими USB ID. Его документы не дают подтверждённого чтения кода нашей80A0 через USB; найденные адреса патчей не переносились на нашу плату: https://github.com/cvanelteren/OpenAula .

Точный образ80A0/1.30 всё ещё не получен. Проверенные ранее USB-чтения настроек и Feature-запрос версии не стали чтением кода. Настройки могли записываться штатными командами при возврате после RGB-опытов; флаг `firmware_writes:false` в сырых отчётах означает отсутствие программирования исполняемой прошивки, **не** утверждение, что все эти команды работают только с RAM.

Для следующего обоснованного шага нужен хотя бы один новый источник: совместимый firmware/recovery-образ, документированный RAM-канал именно80A0 либо подтверждённый способ чтения кода установленной1.30. Без него повторение тех же пакетов не снимает ограничение. Подготовленный запрос точного recovery-файла: [AJAZZ-FIRMWARE-REQUEST.md](AJAZZ-FIRMWARE-REQUEST.md); он не отправлялся.

Неподтверждённые boot/reset/erase/program-команды, снятие защиты и прошивка чужого образа не выполнялись. Эти отрицательные результаты не доказывают принципиальную невозможность другого USB-пути.
