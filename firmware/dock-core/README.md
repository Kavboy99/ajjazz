# Ядро кастомной прошивки дока

Это самостоятельная Rust-библиотека `no_std` без зависимостей, `alloc`, плавающей точки и `unsafe`. **Она не является готовым BIN для AJ159 APEX и не устанавливается на док.** Модель контроллера и аппаратный порт дока1759 пока не подтверждены.

Реализовано:

- Вычисление RGB на самом MCU: постоянный цвет, палитровая волна, дыхание, комета и искры. До4 слоёв, маски до64 логических LED, палитры, яркость, направление, период и смешивание.64 — предел библиотеки, не установленное число диодов дока.
- Пресеты Aurora, Embers, Comet, NeonPulse. Определения находятся в `src/presets.rs`.
- Расписание до8 страниц: часы, цвет, изображение, сохранённая последовательность кадров. Автономная анимация выбирает кадр по прошедшему времени; USB не нужен для каждого кадра.
- Настраиваемые цвета, масштаб и мигание разделителя часов. Время поступает из аппаратного RTC через `TimeOfDay`; наличие и сохранность RTC физического дока этим не подтверждаются.
- Построчный RGB565-рендер: для ширины128 вызывающая сторона выделяет256 байт, вместо32768 байт полного кадра. Числа128×128 не зашиты в движок и не считаются доказанным физическим разрешением панели.
- Общая временная шкала с обработкой переполнения32-битного таймера; частота вывода до60 кадров/с с рациональными дедлайнами и пропуском устаревших кадров. Это частота планировщика; фактическая скорость SPI/LED физического дока не измерена.
- Версионируемая конфигурация слоёв и страниц до236 байт с CRC32, проверкой всех диапазонов и отклонением неизвестных значений. [Формат AJDC](CONFIGURATION.md) предназначен для будущего аппаратного порта; штатный док его не поддерживает. Реализации flash-сохранения пока нет.

## Сборка и проверки

```text
cargo test --manifest-path firmware/dock-core/Cargo.toml
cargo clippy --manifest-path firmware/dock-core/Cargo.toml --all-targets -- -D warnings
cargo build --manifest-path firmware/dock-core/Cargo.toml --target thumbv6m-none-eabi --release
```

Для Windows GNU в данном workspace используется `scripts/check-dock-core.ps1`: он настраивает уже установленный MinGW так же, как основной `scripts/dev.ps1`. Сборка Cortex-M0 проверяет отсутствие зависимости от ОС/FPU/allocator. Она **не определяет MCU дока**; библиотеку также можно собрать для другого подтверждённого Rust target.

Проверки покрывают порядок RGB565 и яркость, непрерывность волны через границу периода, смешивание/маски, выход за предел LED, переполнение таймера, частоту и отсутствие серии запоздалых кадров, полночь, границы страниц, ошибки ресурсов и кадры сохранённой анимации.

## Подключение к реальной плате

Аппаратный порт должен:

1. Предоставить проверенный миллисекундный таймер. Вызывать `Timeline::advance` регулярно; выполнять `FramePacer::due` перед формированием нового кадра.
2. Передать `Scene::render` буфер фактического количества LED и преобразовать логический индекс в установленный порядок проводки. Способ вывода, GPIO, питание LED и DMA определяются по целевому коду/плате.
3. Выбрать `Pages::at`, один раз зафиксировать время RTC и локальный `elapsed_ms` страницы, использовать этот же снимок для всех строк кадра. Это предотвращает смешивание двух кадров анимации при медленной передаче панели.
4. Реализовать `Assets` с проверкой ID, номера кадра, геометрии и границ хранилища. `Assets::row` возвращает логическую строку RGB565; произвольные адреса flash от пользователя не принимаются.
5. Выводить строки через подтверждённый драйвер панели. Ориентация, byte order, инициализация и обратное давление SPI остаются в порте.
6. Реализовать сохранение конфигурации/ресурсов и обработчики USB только после установления разделов памяти и допустимых команд. В текущей библиотеке нет flash-writer, загрузчика, протокола управления или реализации хранения настроек.
7. Сохранить штатные USB/radio/зарядные пути либо доказать их полноценную замену. Встраивание ядра не даёт разрешения стирать родственные образы или неизвестные разделы.

## Пути к завершению аппаратной части

Предпочтительный путь — точный offline/recovery-образ USB-компонента и экранного/RGB-компонента ID1759, проверка загрузчика и порт ядра поверх подтверждённых драйверов. Другой путь — подтверждённое чтение имеющейся flash с восстановлением. Сейчас нормальный USB-протокол такого чтения не дал; найденный чужой дамп PAN108 получен через SWD и не заменяет дамп дока.

Без точного образа, установленной схемы контроллеров и восстановления нельзя считать аппаратный порт законченным. Исследования и конкретные отчёты: [DOCK-FIRMWARE.md](../../docs/DOCK-FIRMWARE.md).
