# Логический формат конфигурации AJDC v1

Этот файл описывает **новый offline-формат нашего ядра**, а не найденный протокол штатной прошивки. Док ID1759 его сейчас не принимает. Файл настроек не является BIN с исполняемым кодом. USB-передача, размещение во flash, атомарное сохранение и выбор аппаратного порта остаются отдельной работой.

Все многобайтные значения — little-endian. Максимальная длина —236 байт. Значения enum заданы явно; Rust layout и `memcpy` структур не используются.

| Смещение | Размер | Поле |
|---|---:|---|
|0|4|ASCII `AJDC`|
|4|2|Версия схемы,1|
|6|2|Длина payload, без12 байт заголовка|
|8|4|IEEE CRC-32 по байтам0..7 и12..конец|
|12|1|Частота планировщика,1..60|
|13|1|Общая яркость RGB,0..255|
|14|1|Число слоёв,1..4|
|15|1|Число страниц,1..8|
|16|29 × число слоёв|Слои в порядке смешивания|
|После слоёв|13 × число страниц|Страницы в порядке показа|

Слой: effect:u8 (`Solid=0, Wave=1, Breathe=2, Comet=3, Sparkle=4`), число цветов:u8 (1..4), четыре RGB-тройки (неактивные строго нулевые), период:u32 (100..60000 мс), число повторов:u8 (1..16), направление:u8 (0/1), непрозрачность:u8, маска:u64. Маска адресует логические индексы; количество и проводка LED дока по ней не предполагаются.

Страница: длительность:u32 (100..3600000 мс), content:u8, payload:8 байт. Неиспользуемые байты payload строго нулевые.

| Content | Payload |
|---|---|
|0, часы|RGB текста:3, RGB фона:3, масштаб:1 (1..8), мигание разделителя:1 (0/1)|
|1, цвет|RGB:3, нули:5|
|2, изображение|ID ресурса:u16, нули:6|
|3, анимация|ID ресурса:u16, число кадров:u16 (1..256), интервал:u16 (16..10000 мс), нули:2|

ID ресурса не является адресом flash. Наличие ресурса, число сохранённых кадров и геометрия проверяются реализацией `Assets` в аппаратном порте до использования.

`Configuration::decode` возвращает новый объект только после проверки всего пакета. Вызывающий код сохраняет текущую конфигурацию при ошибке. Неизвестная версия, enum, лишние байты, неверная длина, CRC или диапазон отклоняются. Буфер короткого `encode` не изменяется. CRC обнаруживает повреждение данных; это не криптографическая подпись и не проверка подлинности прошивки.

Этот формат можно использовать в приложении и на MCU одной и той же библиотекой. Он не даёт восстановления после сбоя питания сам по себе: аппаратное хранилище потребует подтверждённых разделов и схемы фиксации записи.
